## Problems Encountered

The first production apply failed while configuring:

`reserved_concurrent_executions = 2`

The AWS account had only 10 available concurrent executions, and AWS would not allow the reservation because it would reduce unreserved concurrency below the account minimum.

The Lambda had already been created successfully, but Terraform marked it tainted.

## What I Learned

- Terraform applies can partially succeed before returning an error.
- Terraform state and the real AWS resource must both be inspected after a partial failure.
- A tainted resource should not automatically be replaced if the live resource can first be verified as healthy.
- `terraform untaint` can preserve a healthy resource after a failed resource operation.
- Lambda reserved concurrency is limited by the AWS account concurrency pool.
- API Gateway throttling can protect a small serverless endpoint without requiring Lambda reserved concurrency.
- Saved Terraform plans are useful because the exact reviewed change can be applied without replanning.
- A recovery plan should be reviewed as carefully as an initial production plan.
- Terraform convergence after deployment is evidence that configuration and infrastructure agree.
- API access logs should avoid request-body or visitor-content logging when that data is unnecessary.
- An SNS publish does not guarantee notification delivery without a confirmed subscription.
- End-to-end validation should test the complete user-facing path, not only individual AWS resources.
