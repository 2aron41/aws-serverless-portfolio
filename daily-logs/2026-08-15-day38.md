## What I Learned

- Terraform mocks must provide valid computed values when downstream provider validation depends on them.
- CI path filters must match the module actually being changed.
- Data sources can increase Terraform state-object counts even though they do not create AWS resources.
- Production changes are safer when the commit hash, tfvars hash, and saved-plan hash are all pinned before apply.
- CloudWatch alarm actions and OK actions can validate both incident and recovery notification paths.
- Controlled alarm-state testing can validate alerting without deliberately causing a production outage.
- `treat_missing_data = "notBreaching"` fits a low-traffic inquiry service because a lack of requests should not itself cause an incident.
- Business inquiry notifications and infrastructure alert notifications should remain separate.
- A recovery runbook should emphasize investigation before configuration changes.
