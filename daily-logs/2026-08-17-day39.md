## What I Learned

- Frontend cooldowns are useful for accidental duplicate prevention but are not a complete security boundary.
- A client-side memory-only cooldown can be bypassed by refreshing, reopening the page, using another browser context, or calling the API directly.
- Test-first development makes behavior changes easier to verify because the missing behavior is proven before implementation.
- Time-dependent frontend behavior should use a controllable clock in tests.
- Failed requests should not penalize the user by starting a cooldown.
- Existing server-side throttling should be inspected before adding unnecessary new infrastructure.
- Deployment failure exercises are valuable when they fail before AWS authentication and production mutation.
- Exact live-file hash comparison is strong evidence that CloudFront is serving the reviewed frontend artifact.
