## Problems Encountered

- The original Lambda source inspection searched only inside the Terraform module and did not find the handler.
- Terraform packaging inspection showed the source actually lives at:
  - `lambda_src/inquiry_handler.py`
- The first concurrent burst script terminated with exit code 1 because `set -euo pipefail` treated a zero-match grep as failure.
- A read-only diagnostic proved all six requests had already completed safely.
- Neither the 6-request nor 20-request bounded burst produced an HTTP 429.
- API access logs were not immediately visible after the final burst.
- A later read-only inspection showed all 20 access-log events had been delivered.

## What I Learned

- Production load tests should have explicit safety boundaries before they begin.
- A malformed request can be useful for testing infrastructure behavior when the application rejects it before side effects.
- Validation ordering matters because it allowed API traffic testing without generating SNS notifications.
- Shell scripts using `set -euo pipefail` must handle zero-result commands deliberately.
- CloudWatch log delivery can lag behind the request itself.
- Metrics can independently verify request counts when application and access-log behavior need to be reconciled.
- A production experiment should report what was actually observed rather than escalating traffic to force an expected result.
- API Gateway metrics, Lambda metrics, access logs, SNS metrics, and alarms together provide stronger evidence than any single signal.
